# Спецификация: Тонкий клиент веб-чата для Outlook (React + Fluent UI v9)

## 1. Бизнес-цель
Предоставить легковесный, отзывчивый и визуально консистентный веб-чат (боковую панель шириной 320–360px), работающий по принципу «тонкого клиента» через протокол REST/SSE с оркестратором `sherpa-agent-server`. Панель используется менеджерами в Microsoft Outlook для Zero-Click связывания писем со сделками 1С:CRM, уточнения реквизитов, свободного диалога и копирования ссылок 1С.

## 2. Функциональные требования к интерфейсу (UI/UX)

### 2.1. Рендеринг сообщений и Markdown (GFM)
- Отображение сообщений ролей `assistant`, `user`, `system`.
- Полная поддержка Markdown GFM через `react-markdown` + `remark-gfm`: полужирный текст, маркированные списки, таблицы, цитаты.
- **Интерактивные ссылки 1С (`e1cib`):**
  - Ссылки вида `[Текст сделки](e1cib/data/Документ.Сделка?ref=...)` перехватываются.
  - По клику выполняется `navigator.clipboard.writeText(url)` и показывается всплывающий Toast: `✔ Скопировано`.
  - Прямой запуск протокола в ОС блокируется.

### 2.2. Бейджи извлеченных сущностей (Entity Chips)
- Если в `message.metadata.extracted_summary` присутствуют извлеченные сущности (компании, номера сделок, ИНН, суммы), они рендерятся в виде компактных тегов/чипсов над текстом сообщения.

### 2.3. Индикатор шагов исполнения (Streaming Steps)
- Во время автоанализа или запросов в 1С отображается анимированный аккордеон/список шагов:
  - `Обрабатываю письмо...` (running $\rightarrow$ completed)
  - `Ищу подходящие сделки в 1С...` (running $\rightarrow$ completed)

### 2.4. Компактные нумерованные кнопки быстрых ответов (Quick Replies & Keyboard-First)
- Список кнопок из массива `suggestions` отображается внизу над полем ввода.
- Каждая кнопка имеет номер `1.`, `2.`, `3.`, соответствующий горячей клавише на клавиатуре.
- При нажатии цифры `1` (если фокус не в поле ввода с набранным текстом или по Enter) отправляется соответствующий выбор.

### 2.5. Плашка контекстного ответа (Reply Banner)
- Высота плашки $\le 28$px, располагается непосредственно над полем ввода.
- Отображает: `[ ↩ Ответ на: <текст запроса> ]` и кнопку `[✕]`.
- Активируется:
  - Автоматически, если сообщение ассистента требует ввода (`metadata.expected_input`).
  - Вручную при клике на действие `[↩ Ответить]` на сообщении.
- Закрывается:
  - При клике на крестик `[✕]`.
  - По нажатию клавиши `Esc`.
  - При отправке сообщения.
- При закрытии плашки пользователю сохраняется возможность писать свободные вопросы в LLM, а в кнопках действий остается `[ ↩ Указать партнера ]`.

### 2.6. Загрузка файла письма (.msg / .eml)
- Кнопка прикрепления файла или Drag-and-Drop зона для ручной загрузки файла письма при тестировании в браузере.

## 3. Режим Zero-Manual Mocks (Автономный запуск в браузере)
- Веб-чат может быть запущен в режиме `VITE_MOCK_MODE=true` без наличия поднятого бэкенда.
- Моковый провайдер эмулирует ответы `POST /v1/chat/session`, `POST /v1/chat/message`, SSE поток событий и ошибку коллизии `ALREADY_PROCESSED`.

## 4. Сценарии верификации
- **Positive 1 (Zero-Click рендер):** Инициализация $\rightarrow$ отображение шагов стриминга $\rightarrow$ показ сообщения со сделками $\rightarrow$ отображение нумерованных кнопок.
- **Positive 2 (Копирование e1cib):** Клик по ссылке `e1cib` $\rightarrow$ вызов буфера обмена $\rightarrow$ показ Toast `✔ Скопировано`.
- **Positive 3 (Reply UX и Esc):** Появление плашки реплая $\rightarrow$ нажатие `Esc` $\rightarrow$ закрытие плашки $\rightarrow$ ввод вопроса в LLM.
- **Positive 4 (Keyboard-First ввод):** Нажатие `1` $\rightarrow$ отправка выбора первой кнопки.
- **Negative 1 (Обработка ошибки 409):** Эмуляция коллизии $\rightarrow$ показ плашки с ошибкой `ALREADY_PROCESSED` и ссылкой на существующую сделку.
