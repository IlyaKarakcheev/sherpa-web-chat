# sherpa-web-chat

**sherpa-web-chat** — это легковесный автономный веб-интерфейс ассистента «Шерпа» для менеджеров компании-дистрибутора ПО. Интерфейс выполнен в дизайн-системе Fluent UI и оптимизирован для оформления и связывания сделок в **1С CRM**, разбора входящих писем со спецификациями из Outlook, проверки совместимости отечественного ПО (реестр Минцифры РФ), расчета спецификаций и консультаций по прайс-листам.

## 2. Что нового в версии 0.3.0
- **Размещение index.html в корне репозитория и поддержка протокола `file:///`:**
  - Файл `index.html` перенесен в корень репозитория для стандартного локального и серверного запуска.
  - Поддерживается универсальная совместимость: прямой двухкликовый запуск `file:///D:/.../index.html` в любом браузере без необходимости запуска локального веб-сервера.
- **Универсальная классическая и ESM архитектура модулей:**
  - Код полностью разделен на независимые модули по принципу Single Responsibility (`src/core/logger.js`, `src/services/http-sherpa.service.js`, `src/services/service-factory.js`, `src/utils/markdown-renderer.js`, `src/app.js`, `mocks/mock-assistant.js`).
  - Файлы адаптированы для одновременной работы как в браузере через традиционные теги `<script>` (без CORS и блокировок `file:///`), так и в среде Node.js для прогона автотестов.
- **Эмуляция состава сервисов моком и управление подключением модулей к оркестратору:**
  - В мок-режиме состав сервисов формируется динамически провайдером `MockSherpaService` (а не зашит в клиенте чата).
  - Для каждого сервиса (1C CRM, GliNER) в панели параметров поддерживаются 3 состояния:
    - 🟢 `Подключен (Online)` — штатная работа и отображение тега;
    - 🟠 `Подключен (Offline)` — отображение тега, сбой связи обрабатывается в диалоге;
    - ⚪ `Не подключен к оркестратору (Detached)` — модуль не активирован, серый тег скрывается, ассистент сообщает об отсутствии модуля в конфигурации.
- **Подлинный статус связи с оркестратором (Mock и Live):**
  - При запуске в Mock- и Live-режиме клиент отображает стрим-индикатор («Подключение...») в ленте сообщений и временно блокирует элементы ввода (текстовое поле, прикрепление файлов, отправка).
  - В Live выполняется реальный сетевой запрос `GET /api/v1/chat/greeting` к оркестратору; в Mock та же фаза эмулируется с учётом задержки ответа.
  - Если сервер доступен, точка становится зеленой (🟢), элементы ввода разблокируются, отображаются теги сервисов и приветствие.
  - Если оркестратор недоступен, точка остается красной (🔴), теги сервисов скрываются, а в ленте выводится системное сообщение об ошибке связи в красном оформлении (`sender: 'system'`) с чипом «Повторить». Поле ввода остаётся доступным для повторных попыток.
- **Графическая панель «Параметры и диагностика» (Settings & Diagnostics Modal):**
  - Кнопка вызова `[⚙️]` в шапке чата.
  - Выбор режима: `🧪 Mock (Эмуляция)` или `🌐 Live (Боевой сервер)`.
  - Просмотр и копирование журнала событий (`[SYS]`, `[MOCK]`, `[HTTP]`, `[USER]`, `[ASSISTANT]`, `[1C]`, `[GLINER]`).

## 3. Режимы работы и запуск

### 3.1. Прямой запуск в браузере (быстрый старт через `file:///`)
1. Двойным кликом откройте файл `index.html` в корне репозитория в любом браузере (например, `file:///D:/.../sherpa-web-chat/index.html`).
2. Чат сразу готов к работе в автономном режиме с эмулятором `MockSherpaService`.

### 3.2. Запуск через локальный HTTP-сервер
```bash
# Через npx serve из корня репозитория
npx serve . -l 3000

# Либо через встроенный Python
python -m http.server 3000
```
После запуска откройте `http://localhost:3000/` в браузере.

### 3.3. Управление через параметры URL
- Стандартный запуск: `http://localhost:3000/index.html`
- Live-режим: `http://localhost:3000/index.html?mode=live&apiUrl=https://api.sherpa.mont.ru`

## 4. Запуск автоматических тестов

Тесты написаны на встроенном раннере Node.js (`node --test`) без внешних зависимостей:
```bash
npm test
```

Проверяются:
- Юнит-тесты ядровых сервисов (`ChatLogger`, `HttpSherpaService`, `SherpaServiceFactory`, `MarkdownRenderer`, `MockSherpaService`) в `tests/unit.test.js`.
- Сквозные интеграционные сценарии (продажи, 1С CRM, HTTP API, фокус) в `tests/e2e-scenarios.test.js`.
