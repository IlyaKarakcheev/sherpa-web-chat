# Спецификация Server-Driven Markdown и UI-директив «Шерпа Веб-Чат»

**Версия спецификации:** 1.0.0  
**Статус:** Действующий контракт  
**Целевая аудитория:** Разработчики бэкенда (`assistant-orchestrator`), авторы системных промптов LLM и разработчики веб-клиента.

---

## 1. Архитектурные принципы

1. **Server-Driven UI**: Веб-клиент («Шерпа») является «тонким клиентом». Он **не содержит бизнес-эвристик** и **не парсит строки по разделителям** для угадывания сущностей.
2. **Единственный источник истины**: Сервер полностью определяет верстку, вид карточек, варианты ответов и динамический placeholder поля ввода.
3. **Безопасный парсинг**: Веб-клиент экранирует HTML и интерпретирует только описанные в данном контракте подмножества Markdown и пользовательские директивы `:::block`.

---

## 2. Интерактивные кнопки и действия `[Label](cmd:Command)`

Интерактивные кнопки формируются с помощью стандартного синтаксиса ссылок Markdown, где URI начинается с префикса `cmd:`:

```markdown
[Название кнопки](cmd:Текст отправляемой команды)
```

### Варианты стилизации кнопок (Варианты):

1. **Стандартная кнопка (Secondary Action)**:
   ```markdown
   [Показать другие сделки](cmd:Показать другие сделки)
   ```
   *Отображение:* Нейтральная интерактивная кнопка-чип.

2. **Главная акцентная кнопка (Primary Action)** — префикс `!` в названии:
   ```markdown
   [! Обработать открытое письмо](cmd:Обработать открытое письмо)
   ```
   *Отображение:* Синяя акцентная кнопка (Primary button).Префикс `!` автоматически скрывается в UI.

3. **Второстепенная / Нейтральная кнопка (Subtle Action)** — префикс `~` в названии:
   ```markdown
   [~ Отмена](cmd:Отмена)
   ```
   *Отображение:* Нейтральная полупрозрачная кнопка. Префикс `~` автоматически скрывается в UI.

4. **Нумерованные кнопки (быстрый ввод с клавиатуры)**:
   ```markdown
   [1. Сумма 1 000 000 ₽](cmd:Сумма 1 000 000 ₽)
   [2. Ввести сумму вручную](cmd:Ввести сумму вручную)
   ```
   *Правило:* Если кнопка содержит порядковый номер (`1. `, `2. `), пользователь может триггерить команду не только кликом, но и простым вводом цифры `1` или `2` в чат.

## 3. Пользовательские директивы блоков `:::directive`

Директивы контейнеров записываются с помощью `:::название_блока ... :::`.

### 3.1. Динамический Подсказчик Поля Ввода `:::placeholder`

Устанавливает текст placeholder в поле ввода сообщений `textarea` на текущем шаге диалога. Данный блок вырезается из текста сообщения и не отображается в теле пузыря чата.

**Синтаксис (однострочный):**
```markdown
:::placeholder Спросите о сделках 1С, обработайте письмо или запросите подбор ПО... :::
```

**Синтаксис (многострочный):**
```markdown
:::placeholder
Спросите о сделках 1С или выберите команду...
:::
```

### 3.2. Карточка сделки `:::deal-card`

Используется для вывода найденных или предлагаемых сделок CRM.

**А. Интерактивная карточка сделки (Кликабельная)**:
Если заголовок карточки обернут в `[**Заголовок**](cmd:Команда)`, вся карточка становится интерактивной кнопкой.

```markdown
:::deal-card
[**1. #CRM-2026-0854 — АО «ТрансНефть»**](cmd:Связать со сделкой #CRM-2026-0854) :: 71% совпадение
1 420 000 ₽ · Переговоры
Совпадение по ИНН и названию компании из письма
:::
```

**Б. Статическая карточка сделки**:
```markdown
:::deal-card
**#CRM-2026-0854 — АО «ТрансНефть»** :: 71% совпадение
1 420 000 ₽ · Переговоры
:::
```

**Структура строк внутри `:::deal-card`:**
- **Строка 1**: `Заголовок :: Процент/Плашка совпадения` (разделяется `::`).
- **Строка 2**: Метаданные (Сумма, Статус сделки).
- **Строка 3 (опционально)**: Комментарий / Причины совпадения.

### 3.3. Блок ключевых фактов `:::facts`

Используется для компактного вывода ключевых метрик или атрибутов письма/документа.

```markdown
:::facts
- **Партнер (покупатель):** :: ООО «Системные Решения» (ИНН 7701234567)
- **Заказчик:** :: ПАО «Северсталь» (ИНН 3528000597)
- **Сумма сделки:** :: 2 500 000 ₽
:::
```

## 4. Специальные строковые элементы и статусы

1. **Строка статуса анализа (`● Текст`)**:
   ```markdown
   ● Выполняется сопоставление ИНН в 1С CRM...
   ```
   *Отображение:* Выделенный информационный блок цвета бренд-акцента.

2. **Строка успешного завершения / Чекмарк (`✓ Текст`)**:
   ```markdown
   ✓ **Готово**
   ```
   *Отображение:* Строка с зеленой галочкой успешности операции.

3. **Разделитель (`---`)**:
   ```markdown
   ---
   ```
   *Отображение:* Горизонтальная линия-разделитель в блоке ответа.

## 5. Стандартные элементы Markdown

- **Заголовки**: `# `, `## `, `### `
- **Выделения**: `**жирный**`, `*курсив*`, `***жирный курсив***`
- **Моноширинный код**: `` `e1cib/data/Документ.Сделка?ref=...` `` (используется для навигационных ссылок 1С с поддержкой клика для копирования)
- **Списки**: маркированные (`- `, `* `) и нумерованные (`1. `, `2. `)
- **Таблицы (GFM)**:
  ```markdown
  | Продукт | Вендор | Совместимость с 1С |
  | :--- | :--- | :--- |
  | **Postgres Pro Standard** | Postgres Professional | Полная |
  ```

```markdown
:::deal-card
[**1. #CRM-2026-0854 — АО «ТрансНефть»**](cmd:Связать со сделкой #CRM-2026-0854) :: 71% совпадение
1 420 000 ₽ · Переговоры
Совпадение по ИНН и названию
:::

:::deal-card
[**2. #CRM-2026-0790 — ООО «Газпром Автоматизация»**](cmd:Связать со сделкой #CRM-2026-0790) :: 38% совпадение
5 800 000 ₽ · Согласование
:::

[3. Создать новую сделку](cmd:Создать новую сделку)  
[~ Отмена](cmd:Отмена)

:::placeholder Выберите сделку (1-2), создайте новую (3) или отмените... :::
```

## 7. Рекомендации для разработчиков LLM-оркестратора

1. Все действия, требующие клика пользователя, оборачивайте в `[Текст](cmd:Команда)`.
2. Команда в `cmd:Команда` должна быть точно сформулированным текстом, который сервер ожидает получить при клике пользователя.
3. Всегда завершайте ответ директивой `:::placeholder ... :::`, чтобы контекстно подсказывать пользователю следующий шаг.
